# skill-optimize — 技能观察记录消费与优化落地

## 目标

把「技能观察」机制（0.35.2）沉淀的复盘记录转化为**经过用户确认的、最小的**技能优化，防止噪音建议直接污染 SKILL.md。

## 前提（单一事实源）

- 观察状态与复盘记录：`_governance/skill-observations.json`
  - 每技能条目：`observing`（开关）、`entries[]`（复盘记录，每条含 `findings[]` / `suggestions[]` / `status: pending|handled`）
  - 开关由 Skill 管理面板控制；本技能**只读 observing，不修改开关**。
- 写作判据：`writing-for-agents`（大型文档参考，按需加载，不逐字套用）。

## 步骤

### 0. 读观察记录，列出待处理项

1. 读 `_governance/skill-observations.json`；
2. 列出所有含 `status != handled/optimized` 建议的技能，按 `pendingSuggestions` 数降序；
3. 展示给用户，确认本次处理范围（全部 / 指定技能 / 指定记录 id）；
4. 用户未指定时默认**全部**。

### 1. 加载判据

加载 `writing-for-agents` 技能，提取与本次建议相关的判据（结构、触发条件、长度、否定式表达、单一事实源等），只作为评估参照。

### 2. 逐条去噪评估

对每条建议，先判断是否值得优化，**剔除必须给原因**：

- **no-op**：建议内容 SKILL.md 已覆盖或已等效表达 → 剔除；
- **单次过拟合**：只来自一次任务的偶发情况，无复现证据 → 剔除（若同一问题出现 ≥2 次记录则保留）；
- **重复**：与其他建议/已有内容重复 → 合并或剔除；
- **相关性丧失**：建议与技能职责无关或违背用户既定决策 → 剔除。

剔除理由可引用**他条记录/机制现状**（证据可跨记录：同源重复次数、机制版本缓解、他条实测证伪），不要求单条建议自证。

保留的建议标注：涉及的小节、问题类型（模糊/重复/缺失/误导）、建议的改法。

### 3. 合并同类，出最小方案

1. 同类建议合并为一条最小改动（优先：删冗余 > 改措辞 > 增补步骤/判据）；
2. 每个技能汇总为一组改动，列出：`SKILL.md` 目标小节、改前 → 改后（或删除）、影响面；
3. **只改最小范围**，不做顺手重构；涉及行为/设计变更（改变技能职责、步骤语义、判据门槛）先停下列出变更，等用户确认。

### 4. 用户确认

展示方案，等用户确认后再落地。用户可逐条接受/拒绝。

### 5. 落地

- **插件技能**（dsh-manager 包内）：按 local-governance 流程走版本 bump（四件套）→ 打包 → 装配 → 镜像同步 → 账本，版本按铁律 6 只增不覆盖；**多技能改动可合并单次发版**（同一版本号带出全部技能变更），减少发版次数；
- **全局/项目技能**：直接改 SKILL.md 文件（注意观察约定块 `<!-- dsh-observe:start -->`…`<!-- dsh-observe:end -->` 要原样保留，避免误删）。

### 6. 验证

- frontmatter 完整（name/description）且能正常加载（skill 工具返回新内容）；
- 步骤/判据改动后语义无矛盾、无断链（相对路径资源仍可解析）；
- 插件技能：热重载后注册生效，`skill('<名>')` 返回新内容。

### 7. 写回

对已落地的记录：`status=handled`、`handledAt`、该技能 `optimizedAt`、`revision+1`、清空已处理建议；更新文件 `updatedAt`。被剔除的建议在记录里加 `dismissed: true` + 原因，保留审计痕迹。

## 完成判据

- 每条待处理建议都有结论（落地 / 剔除+原因 / 挂起等用户决策）；
- 所有落地改动都经过用户确认；
- `skill-observations.json` 状态与实况一致（handled 记录、revision、updatedAt 已写回）；
- 插件技能改动已按 local-governance 完整发版（含账本），不是裸改文件。
